# 什么是 marimo

## 一个像电子表格的 Python notebook

marimo 是一个 **reactive Python notebook**。所谓 reactive，指的是"响应式"——当你修改了某一个 cell（单元格）之后，所有依赖它的 cell 都会自动重新计算并更新结果，就像 Excel 电子表格一样：改一个格子，引用它的格子立刻跟着变。

在传统编程里，变量是一次性赋值的，后面的代码改了前面的定义，你必须手动重新运行所有受影响的代码才能看到新结果。而在 marimo 里，你只需要改一个 cell，整个 notebook 的状态会自动收敛到一致。这种"改一处、自动传播"的体验，正是 reactive 编程范式带给 notebook 的核心价值。

## 三个核心能力

marimo 把自己定位为一个"下一代 notebook"，它围绕三个核心能力构建：

1. **Reactive（响应式执行）**：基于静态分析自动建立 cell 之间的依赖关系，构成有向无环图（DAG）。任一 cell 修改后，仅重算其下游依赖，既保证一致性又避免冗余计算。
2. **Pure Python（纯 Python 文件即 notebook）**：notebook 本身就是一个 `.py` 文件，用 `cell` 装饰器或函数标记每个 cell。这意味着你可以用 `git diff` 正常查看改动、用任意编辑器打开、用 `ruff`/`black` 格式化，彻底告别 JSON 格式的 `.ipynb`。
3. **Notebook 即 Web App**：同一个 `.py` 文件，既能作为交互式 notebook 用于探索，也能一键转化为带 UI 控件的 Web 应用部署给最终用户。notebook 和 app 不再是两套代码。

## 与 Jupyter 的本质区别

Jupyter 是当下最流行的 notebook 工具，但它的执行模型是**命令式**的：cell 之间没有显式依赖关系，执行顺序完全由用户点击决定。这导致了一个臭名昭著的问题——**隐藏状态**：你看到的代码和实际运行的内存状态可能完全不一致，因为你可以乱序执行、反复执行某个 cell，而 notebook 不会告诉你哪些 cell 的输出已经"过期"了。

marimo 的本质区别在于：它把 notebook 当作一个**纯函数的集合**来看待。每个 cell 的输出只取决于它引用的变量，而变量来源于其他 cell 的定义。通过 AST 静态分析，marimo 能精确知道每个 cell 定义了哪些变量（defs）、引用了哪些变量（refs），从而自动构建依赖图。执行时按拓扑排序进行，任何修改都会触发依赖链上所有受影响 cell 的重算，并短路掉无关分支。

简单说：**Jupyter 把 notebook 当作一串可独立运行的代码块，marimo 把 notebook 当作一张会自动重算的计算图**。前者把"保持状态一致"的责任推给了人，后者把这个责任交给了系统。这正是本项目"从零实现 marimo"要复现的核心思想。
