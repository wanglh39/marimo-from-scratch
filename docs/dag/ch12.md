# 图论基础

在进入 `CellGraph` 的源码之前，我们需要先把几个图论概念弄清楚。marimo 把每个 cell 看作图中的一个节点，把 cell 之间的变量依赖关系看作有向边，从而把整本 notebook 建模成一张有向图。理解这张图的性质，是理解后续增量执行、短路、拓扑排序等所有机制的前提。

## 有向图

有向图（Directed Graph）由一组顶点 $V$ 和一组有向边 $E$ 组成，每条边是一个有序对 $(u, v)$，表示从 $u$ 指向 $v$。在 marimo 中，顶点是 cell，边 $(A, B)$ 表示"cell A 定义了某个变量，而 cell B 引用了这个变量"，也就是 B 依赖 A，数据从 A 流向 B。边的方向与数据流方向一致，这一点很重要，后面求"后代"时就是顺着数据流方向往下找。

## DAG

DAG 是 Directed Acyclic Graph 的缩写，即有向无环图。"无环"意味着不存在一条从某个顶点出发、经过若干条边又回到自身的路径。为什么 notebook 必须是 DAG？假设 cell A 依赖 cell B，cell B 又依赖 cell A：A 要先执行才能给 B 提供变量，B 又要先执行才能给 A 提供变量，两者互相等待，无法排出一个合理的执行顺序。因此 marimo 在构建图之后会显式检测环，一旦发现就抛出 `CyclicDependencyError`，拒绝执行。

## 拓扑排序

拓扑排序（Topological Sort）是把 DAG 的所有顶点排成一个线性序列，使得对任意一条边 $(u, v)$，$u$ 都排在 $v$ 前面。这样的序列就是一个合法的执行顺序：每个 cell 执行时，它依赖的所有 cell 都已经执行过了。一个 DAG 可能有多种拓扑序，marimo 用 `sorted` 对同一入度层里的节点按 id 排序，保证每次得到同一个序列，从而让执行结果可复现。`CellGraph.topological_order` 用的就是 Kahn 算法，我们会在第 17 章详细拆解。

## cell 间依赖为什么构成 DAG

从语义上看，每个 cell 显式声明了自己定义的变量（`defs`）和引用的变量（`refs`）。边的产生规则是：若 cell B 的 `refs` 里有变量 $x$，而 cell A 的 `defs` 里有 $x$，则连一条 $A \to B$。这条规则只依赖静态分析得到的符号集合，不依赖运行时值。只要用户不写出循环引用（这通常意味着逻辑矛盾），自然得到一张 DAG。即便用户不小心造出环，`_rebuild` 之后的拓扑排序也会立即报错，把问题挡在执行之前。这就是 marimo 用图来组织 cell 的根本原因：把"执行顺序"这个原本隐式、易错的问题，转化成一个有明确算法解的图论问题。
