# 与 .ipynb 对比：JSON vs Python

`.ipynb` 是 Jupyter 的事实标准，本质是一个 JSON 文档。marimo 的 `.py` 格式是对它的反思。这一章把两者放在一张桌上对比，看清各自取舍。

## 结构对比

**.ipynb** 是嵌套 JSON：

```json
{
  "cells": [
    {"cell_type": "code", "source": ["x = 5\n"], "outputs": [...], "execution_count": 1},
    {"cell_type": "markdown", "source": ["# Title\n"]}
  ],
  "metadata": {...}, "nbformat": 4
}
```

代码是 `source` 字段里的**字符串列表**（每行一个元素），输出塞在 `outputs` 里，执行计数、元数据层层包裹。一个 10 行代码的 cell，JSON 可能占 30 行。

**.py** 是平面 Python：

```python
@app.cell
def __(mo):
    x = 5
    return (x,)
```

代码就是代码，没有字符串编码层。4 行就是 4 行。

## diff 友好性

这是 marimo 格式最大的卖点。改一行代码：

- **.ipynb**：JSON 里 `"source": ["x = 5\n"]` 变成 `"source": ["x = 6\n"]`，diff 显示这行 JSON 变了。但若改动导致 JSON 重新格式化（很多工具会），diff 可能爆炸成几十行。
- **.py**：`x = 5` 变 `x = 6`，diff 就一行。干净、可读、可 review。

挪 cell 顺序：

- **.ipynb**：JSON 数组重排，diff 显示一大片删除 + 一大片新增。
- **.py**：函数顺序变了，diff 同样显示移动，但因为每个 cell 是独立函数，语义边界清晰，reviewer 一眼看出是挪动而非重写。

## 可执行性

- **.ipynb**：不能直接 `python notebook.ipynb`，必须 `jupyter nbconvert --to script` 或 `jupyter execute`。要装 Jupyter。
- **.py**：`python notebook.py` 直接跑。任何有 Python 的机器都行。

这让 marimo notebook 能直接当脚本用、当模块 import、塞进 CI 跑测试，而 `.ipynb` 做这些都需要额外工具链。

## 输出存储

- **.ipynb**：输出（stdout、图表 base64、HTML）全存进文件，导致文件巨大且频繁变动——重跑一次所有输出都变，git 里全是噪声。
- **.py**：默认不存输出，文件只含代码。输出是运行时产物，不进版本控制。

代价是重开 notebook 要重算；但 reactive notebook 本来就会按需重算，这个代价可接受，换来的是永远干净的 git 历史。

## 往返测试

marimo 的往返测试验证 `py_to_graph(graph_to_py(g)) == g`：

```python
def test_roundtrip(tmp_path):
    g = make_sample_graph()
    py = graph_to_py(g)
    f = tmp_path / "nb.py"
    f.write_text(py)
    g2 = py_to_graph(f.read_text())
    assert graphs_equal(g, g2)
```

`.ipynb` 的往返则复杂得多：JSON 解析回来要处理 `source` 是字符串还是列表、`outputs` 的各种 mime 类型、`execution_count` 是否保留……格式规范本身就有歧义。而 `.py` 的往返只依赖 Python 语法——语法无歧义，`ast.parse` 是确定性的。

## 总结

| 维度 | .ipynb | .py |
|------|--------|-----|
| 格式 | JSON | Python |
| 可执行 | 需工具 | 直接 `python` |
| diff | 噪声大 | 干净 |
| 输出 | 内嵌 | 不存 |
| 往返 | 复杂 | 简单 |

marimo 选 `.py` 不是为了标新立异，而是因为 notebook 的本质是"带依赖关系的代码集合"，而 Python 函数 + 装饰器天然能表达这个结构，何必再套一层 JSON。
