# 断线重连：WebSocket 断开处理

WebSocket 连接不是永远不断——网络抖动、后端重启、浏览器休眠都可能断开。notebook 要可用，就得处理重连。教学版做最简方案，生产版 marimo 做得更完整，这一章讲清两者。

## 断开的触发场景

- **网络抖动**：WiFi 切换、瞬断；
- **后端重启**：开发时改后端代码、uvicorn --reload；
- **浏览器休眠**：笔记本合盖、切后台标签页；
- **服务端崩溃**：执行了 `os.exit` 或 OOM。

断开后前端 `WebSocket.onclose` 触发，此时若不处理，用户再点 Run 会发现没反应——消息发不出去。

## 教学版策略：重连 + 全量同步

最简单有效的方案：

```typescript
useEffect(() => {
  let ws: WebSocket;
  let retry: number;

  function connect() {
    ws = new WebSocket("ws://localhost:8000/ws");
    ws.onopen = () => {
      setConnected(true);
      ws.send(JSON.stringify({type: "get_state"}));
    };
    ws.onclose = () => {
      setConnected(false);
      retry = window.setTimeout(connect, 1000);
    };
    ws.onmessage = (e) => { /* dispatch */ };
  }
  connect();
  return () => { clearTimeout(retry); ws.close(); };
}, []);
```

断开后 1 秒重试，重连成功立即发 `get_state` 拉全量状态。后端 `NotebookSession` 在新连接进来时重建（教学版不持久化 session，所以重连后 notebook 回到上次保存到磁盘的状态，未保存的改动丢失）。

这是"无状态重连"——简单但代价是丢运行时状态（变量值、输出）。对教学演示够用，因为演示时改动都会即时保存到 `.py` 文件。

## 生产版的增强

生产 marimo 做几件事让重连更顺：

1. **session 持久化**：后端不随连接断开销毁 session，而是保留一段时间（比如 30 秒），同 notebook 的新连接复用旧 session，变量值都在；
2. **增量同步**：重连后不只发全量 state，还发"你断开期间发生的 cell_result 队列"，前端 replay，恢复到断开时一致的状态；
3. **指数退避**：重试间隔 1s → 2s → 4s → ...，避免后端挂了时前端疯狂重连；
4. **心跳**：定期 ping/pong，及时检测半开连接（TCP 连接还在但对端已死）。

## 前端 UX 提示

断线期间要给用户明确反馈，不能静默失败：

- 顶部显示红色"已断开，重连中…"指示器；
- 编辑器仍可编辑（代码存前端 state），重连后批量 `update_cell` 同步过去；
- Run 按钮置灰或点击时提示"未连接"；
- 重连成功变绿色"已连接"，自动触发 `get_state`。

教学版 `App.tsx` 顶部一个 `connected ? "🟢" : "🔴"` 指示器即可。

## 为什么教学版不做持久化 session

持久化 session 要解决：session 标识（哪个连接属于哪个 notebook）、过期清理、内存中 Python 命名空间保活（不能 GC 变量）、并发安全。这些是工程量，与"理解 notebook 通信"的教学目标无关。教学版让重连 = 重新加载文件，把复杂度留给生产版。

断线重连是 notebook 可用性的底线——不处理就是"改一下后端前端就废了"，处理了开发体验顺滑很多。教学版用最简方案演示核心思路，理解了再去看生产版增强就不难。
