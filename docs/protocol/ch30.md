# cell 状态机：IDLE → RUNNING → DONE/ERROR/STALE

每个 cell 在执行过程中有状态，前端要据此显示图标、后端要据此调度。marimo 给 cell 定义了一个小状态机，状态转换由执行事件驱动。

## 五个状态

- **IDLE**：初始或已就绪，未执行或上次执行结果仍有效；
- **RUNNING**：正在执行；
- **DONE**：执行成功，输出有效；
- **ERROR**：执行抛异常，输出是 traceback；
- **STALE**：上游 cell 改了，本 cell 的输出可能过期，需要重算。

## 状态转换图

```
IDLE ──run──→ RUNNING
RUNNING ──success──→ DONE
RUNNING ──exception──→ ERROR
DONE ──upstream_changed──→ STALE
STALE ──run──→ RUNNING
ERROR ──run──→ RUNNING
任意 ──code_edited──→ STALE（若曾执行过）
```

关键转换：

1. **IDLE → RUNNING**：用户点 Run 或被上游重算触发；
2. **RUNNING → DONE**：执行无异常，输出存好；
3. **RUNNING → ERROR**：捕获到异常，存 traceback；
4. **DONE → STALE**：上游任一 cell 的 defs 变了（代码改了或重算产出新值），本 cell 标 stale；
5. **STALE → RUNNING**：重算触发。

## 后端如何维护状态

`NotebookSession` 在执行 cell 时更新状态：

```python
async def run_cell(self, cid):
    cell = self.graph.cells[cid]
    cell.status = "RUNNING"
    await self._broadcast_state()
    try:
        result = await self._execute(cell)
        cell.status = "DONE"
        cell.result = result
    except Exception as e:
        cell.status = "ERROR"
        cell.result = {"exception": traceback.format_exc()}
    await self._broadcast_result(cid)
    self._propagate_staleness(cid)
```

执行前先置 RUNNING 并广播（前端立即显示转圈），执行完置 DONE/ERROR 再广播结果。最后 `_propagate_staleness` 把下游 cell 标 STALE——但注意，刚执行成功的 cell 的下游不是 stale，而是可能需要重算，marimo 的 reactive 策略是**自动重算下游**而非仅标 stale。教学版可选：要么自动重算（reactive），要么只标 stale 等用户手动 run（懒求值）。

## 前端同步

前端 `useNotebook` hook 收到 `cell_result` 消息时更新对应 cell 的状态和结果：

```typescript
case "cell_result":
  setCells(prev => prev.map(c =>
    c.id === msg.cell_id
      ? {...c, status: msg.status, result: msg.result}
      : c
  ));
  break;
```

收到 `state` 消息时整体替换。状态变化驱动 React 重渲染，状态图标、输出区域、stale 高亮都自动更新。

## 为什么要 STALE 而非直接重算

纯 reactive（任何上游变就立即重算）在拖滑块时会导致下游每帧重算，卡顿。引入 STALE 中间态让前端能显示"过期"提示，由用户决定何时重算，或由 debounce 后的自动重算处理。这是响应式与可控性的折中。

状态机虽小，但让前后端对"cell 现在什么情况"有统一语言，避免了"前端显示 running 但后端早结束了"这种不同步问题。
