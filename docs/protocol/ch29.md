# 消息协议设计：请求、响应、事件

WebSocket 只提供传输通道，上面跑什么消息、什么格式、怎么区分类型，需要协议设计。marimo 教学版的协议定义在 `protocol.py`，是一套简单的 JSON 文本帧协议。

## 三类消息

所有消息分三类：

**请求（Request）**——前端发给后端，要求执行某操作：
- `get_state`：请求当前完整 notebook 状态；
- `update_cell`：更新某 cell 的代码（不执行）；
- `run_cell`：执行某 cell（可能触发下游重算）；
- `run_all`：执行所有 cell；
- `add_cell` / `remove_cell`：增删 cell；
- `ui_event`：UI 组件事件（滑块值变化、按钮点击等）。

**响应与事件（Response/Event）**——后端发给前端：
- `state`：完整状态快照（响应 `get_state` 或重连时）；
- `cell_result`：某 cell 执行结果（stdout、output、exception）；
- `graph_changed`：图结构变化（cell 增删或依赖改变）；
- `error`：错误通知。

## JSON 帧格式

每条消息是一个 JSON 对象，必有 `type` 字段：

```json
{"type": "run_cell", "cell_id": "c2"}
```

```json
{"type": "cell_result", "cell_id": "c2", "stdout": "hello\n", "output": {"data": "5", "type": "number"}, "status": "done"}
```

```json
{"type": "ui_event", "component_id": "slider_0", "value": 42}
```

用 `type` 字段做枚举分发，比用 WebSocket 的 opcode（文本/二进制帧）更灵活——能在一个通道上混跑多种消息类型，前端 `switch(msg.type)` 即可路由。

## serialize_output：输出序列化

cell 执行后的 Python 对象要序列化成 JSON 能承载的形式。`serialize_output` 做这件事：

```python
def serialize_output(obj):
    try:
        json.dumps(obj)
        return {"data": obj, "type": "json"}
    except TypeError:
        return {"data": repr(obj), "type": "repr"}
```

先试 `json.dumps`，能序列化就原样发（前端拿到原始结构能交互式渲染）；不行就退回 `repr(obj)` 发字符串。比如 numpy 数组不能 JSON 序列化，就发 `repr` 让前端当文本显示。生产版会针对 matplotlib 图、pandas 表等做特殊处理（转 base64 PNG、HTML 表），教学版只做这两档。

## make_cell_info / make_state_message

```python
def make_cell_info(cell, result=None):
    return {
        "id": cell.id,
        "code": cell.code,
        "refs": list(cell.refs),
        "defs": list(cell.defs),
        "status": cell.status,
        "result": result,
    }

def make_state_message(graph):
    return {
        "type": "state",
        "cells": [make_cell_info(c) for c in graph.cells.values()],
        "edges": list(graph.edges),
    }
```

`make_cell_info` 把一个 cell 打包成前端需要的全部字段：代码、依赖、状态、结果。`make_state_message` 把整图打包，用于初始同步或重连。

## 为什么不用 protobuf / msgpack

教学版选 JSON 是因为浏览器原生支持 `JSON.parse`、Python 标准库带 `json`，零依赖、可读、好调试。protobuf 更省带宽但需要 schema 编译，msgpack 更快但调试不直观。对教学项目，JSON 的简单性压倒性能考虑。生产版 marimo 在大 notebook 下会感受到 JSON 序列化开销，但协议设计本身不变，只是换序列化器。

这套协议的精髓在于：**用 `type` 字段做枚举、用 JSON 做载体、用一条 WebSocket 连接复用所有消息类型**。简单、可扩展、好调试。
