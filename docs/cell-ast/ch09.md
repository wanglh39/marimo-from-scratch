# 提取 defs 与 refs

有了前两章的基础，现在实现 `ast_analyzer.py` 的核心：给定一段代码，返回 `defs` 和 `refs` 两个集合。我们的目标是函数 `analyze_cell(code) -> (defs, refs)`，例如 `analyze_cell("y = x + 1")` 应返回 `({"y"}, {"x"})`。

## defs：顶层绑定

`defs` 收集的是"执行完这个 cell 后，会在 cell 作用域里新建或覆盖的变量名"。关键在于**只看顶层语句**——函数体里的局部变量不算 cell 的 def。因此我们遍历 `tree.body`（而不是 `ast.walk`），对每种语句类型取出绑定名：

```python
def _extract_top_level_defs(tree):
    defs = set()
    for stmt in tree.body:
        if isinstance(stmt, ast.Assign):
            for t in stmt.targets:
                defs |= _names_in_target(t)
        elif isinstance(stmt, (ast.FunctionDef, ast.ClassDef, ast.AsyncFunctionDef)):
            defs.add(stmt.name)
        elif isinstance(stmt, ast.Import):
            for alias in stmt.names:
                defs.add(alias.asname or alias.name.split('.')[0])
        elif isinstance(stmt, ast.ImportFrom):
            for alias in stmt.names:
                if alias.name == '*':
                    continue                # 星号导入无法静态分析
                defs.add(alias.asname or alias.name)
        elif isinstance(stmt, ast.For):
            defs |= _names_in_target(stmt.target)
        elif isinstance(stmt, ast.With):
            for item in stmt.items:
                if item.optional_vars is not None:
                    defs |= _names_in_target(item.optional_vars)
        elif isinstance(stmt, ast.AnnAssign) and stmt.target:
            defs |= _names_in_target(stmt.target)
        elif isinstance(stmt, ast.NamedExpr):           # 海象运算符 :=
            defs |= _names_in_target(stmt.target)
    return defs
```

`_names_in_target` 递归处理解包：`Name` 返回 `{id}`，`Tuple`/`List` 返回各元素之和，`Starred` 取其内部。这样 `(a, b) = ...` 能同时拿到 `a` 和 `b`。

## refs：所有 Load 名减去局部与 builtins

`refs` 的思路更直接：扫遍整棵树，收集所有 `ctx=Load` 的 `Name`，然后减去两样东西——**函数内部局部变量**和 **builtins**。

```python
def _extract_refs(tree):
    loads = {n.id for n in ast.walk(tree)
             if isinstance(n, ast.Name) and isinstance(n.ctx, ast.Load)}
    locals_ = _collect_function_locals(tree)          # 形参 + 函数内赋值
    builtins_ = set(dir(__builtins__))
    return loads - locals_ - builtins_
```

为什么减局部变量？考虑 `def f(x): return x + 1`，函数体里的 `x` 是 `Load`，但它不是 cell 的依赖，只是形参。`_collect_function_locals` 会进入每个 `FunctionDef`/`AsyncFunctionDef`，收集其形参和函数体内 `Store` 的名字，把它们标记为局部。注意：函数**名本身** `f` 是 cell 的 def，由上一节处理，不在这里。

减 builtins 是为了让 `print`、`range`、`len`、`open` 这类全局可用名不算依赖——否则几乎每个 cell 都会"依赖" `print`，DAG 会被无意义的边塞满。

## AugAssign：读-改-写

`x += 1` 是个特殊情况。它等价于 `x = x + 1`，对 `x` 既是读也是写。但 `ast.walk` 在 `AugAssign.target` 上看到的 ctx 是 `Store`，所以默认不会被 `Load` 扫描到，refs 会漏掉 `x`。我们的处理是：遇到 `AugAssign`，把它的 target 名同时加入 defs 和 refs：

```python
if isinstance(stmt, ast.AugAssign):
    name = _names_in_target(stmt.target)
    defs |= name
    refs |= name
```

这样 `x += 1` 得到 `defs={"x"}`、`refs={"x"}`，语义正确：本 cell 定义了 `x`（会覆盖旧值），同时也引用了 `x`（需要上游先提供初值）。

## 一个完整例子

```python
analyze_cell("y = x + 1")
# defs = {"y"},  refs = {"x"}

analyze_cell("import numpy as np\nv = np.array([1,2])")
# defs = {"np", "v"},  refs = set()   # np.array 是属性访问，不是 Name

analyze_cell("def f(a): return a + b")
# defs = {"f"},  refs = {"b"}         # a 是局部，b 是外部依赖

analyze_cell("x += 1")
# defs = {"x"},  refs = {"x"}
```

这些结果正是 DAG 构建所需要的：cell 之间的边由"后继的 refs ∩ 前驱的 defs"决定。
