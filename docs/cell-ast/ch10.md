# 作用域与边界情况

上一章给出了提取 defs/refs 的主干逻辑，但真实代码里有很多边界情况会让朴素的实现出错。这一章集中讨论作用域相关的问题，以及教学版做了哪些简化。

## 函数内部局部变量不算 cell 的 def

考虑：

```python
def make_counter():
    count = 0
    def step():
        nonlocal count
        count += 1
        return count
    return step
```

如果天真地把所有 `Store` 的 `Name` 都算作 cell 的 def，我们会把 `count`、`step` 都收进 defs，这是错的——它们是 `make_counter` 的局部变量，cell 执行结束后在外部不可见。正确的做法是：**只收集顶层语句直接产生的绑定**作为 defs；函数体内部的赋值由 `_collect_function_locals` 单独处理，仅用于从 refs 中剔除。

实现上，`_extract_top_level_defs` 遍历 `tree.body`，不递归进入 `FunctionDef`/`ClassDef` 的 `body`；而 `_collect_function_locals` 才会进入函数体，把形参和内部 `Store` 名收集起来。两者配合，既不让局部变量污染 defs，也不让它们污染 refs。

## comprehension 变量是局部的

Python 3 里，列表/集合/字典推导式与生成器表达式都有自己的作用域，循环变量不会泄漏到外层：

```python
squares = [x**2 for x in range(10)]
# 执行后 x 在外部不可见
```

因此推导式里的 `x` 既不是 cell 的 def，也不是 cell 的 ref。但 `ast.walk` 会把 `x` 当成 `Store` 的 `Name` 节点吐出来，如果不去处理，`x` 可能被误算进 defs。

教学版的做法：在收集局部变量时，把所有 `comprehension` 节点（`ListComp`、`SetComp`、`DictComp`、`GeneratorExp` 的 `generators` 字段）里的 `target` 名也加入局部集合，从而在 refs 计算时被减掉；同时在 `_extract_top_level_defs` 里，推导式不是顶层语句的"直接绑定目标"（它只是 `Assign.value` 的一部分），所以不会进入 defs。最终 `squares = [x**2 for x in range(10)]` 得到 `defs={"squares"}`、`refs=set()`（`range` 是 builtin 被过滤）。

## 星号导入无法静态分析

```python
from module import *
```

星号导入会把 `module` 里所有公共名字绑定到当前作用域，但这些名字的列表只有在**运行时**才能拿到（取决于 `module.__all__` 或 `dir(module)`）。静态 AST 看不到这些名字，因此无法把它们填进 defs。

教学版的选择是**跳过**：遇到 `alias.name == '*'` 时既不加入 defs，也不报错。这意味着含星号导入的 cell 会被认为"不定义任何变量"，可能导致 DAG 漏边。这是有意为之的简化——正确处理需要导入并执行该模块，已经超出静态分析范畴。生产版 marimo 会对星号导入发出警告，建议用户改用具名导入。

## global / nonlocal 未处理

```python
counter = 0
def inc():
    global counter
    counter += 1
```

`global counter` 声明意味着函数内对 `counter` 的赋值其实作用于 cell 作用域。严格来说，这种情况下 `counter` 应该算 cell 的 def（因为 `inc()` 被调用后会改写它），而且 `counter` 在 `inc` 内部的 `Load` 也不应被当作局部剔除。完整处理需要识别 `Global`/`Nonlocal` 节点并调整作用域模型。教学版**不处理**这两个声明，把它们的影响忽略，以保持代码简单。这在大多数 notebook 场景下够用，因为 `global`/`nonlocal` 在数据分析代码里很少见。

## builtins 过滤

最后强调 builtins 过滤的意义。`print`、`open`、`range`、`len`、`Exception`……这些名字在任意 cell 里都是 `Load`，但它们不来自任何上游 cell，而是 Python 内置。如果不剔除，每个调用 `print` 的 cell 都会"依赖"一个不存在的 `print` cell，DAG 里满是虚假边。实现上用 `set(dir(__builtins__))` 作为过滤集，从 refs 中减去。注意：如果用户自己写了 `print = my_print` 重绑定，`print` 会出现在 defs 里，这时它就不再是 builtin 而是普通变量——教学版不区分这种重绑定，统一先减 builtins，对绝大多数场景足够。

这些边界处理加在一起，才让 `analyze_cell` 在面对真实 notebook 代码时给出可信的 defs/refs。
