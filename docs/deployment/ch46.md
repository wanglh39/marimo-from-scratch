# 源码导读与对比

最后一章我们把视角拉高：看真实 marimo 的源码结构，把它与 Streamlit、Dash 对比，并诚实地列出教学版为保持简洁而未实现的挑战。

## marimo 源码结构

真实 marimo 的源码大致分为以下几块。`marimo/` 核心包包含 `_ast/`（AST 分析，提取 cell 间的依赖关系）、`_runtime/`（执行器、session、数据流）、`_server/`（FastAPI 服务、WebSocket、API 模型）、`_output/`（富文本输出格式化）、`_plugins/`（UI 组件系统，称为 plugin）。前端 `frontend/` 是一个 ISlands 架构的 React 应用，包含 `editor/`、`components/`、`core/` 等模块。与教学版相比，真实版最显著的扩展在 AST 分析——它能静态分析 cell 代码的引用关系，无需执行即可构建依赖图，这使得 cell 重跑的依赖追踪精确到变量级别，而非教学版的 cell 级别。

## 与 Streamlit 对比

Streamlit 的模型是"自顶向下脚本重跑"：每次用户交互，整个脚本从头到尾重新执行一遍，通过 `@st.cache` 装饰器缓存昂贵计算。优点是心智模型简单，缺点是脚本变长后重跑开销巨大。marimo 的模型是"细粒度 reactive"：只有依赖变化的 cell 重跑，无需手动加缓存装饰器。代价是 marimo 需要分析 cell 间的依赖关系，实现复杂度更高。Streamlit 的 UI 组件是函数调用（`st.slider()` 返回值），marimo 的组件是持久化对象，这使得 marimo 的组件状态在 cell 重跑间自然保持，而 Streamlit 每次重跑都重建组件。

## 与 Dash 对比

Dash 的模型是"显式回调注册"：用户定义 `@app.callback` 把输入组件的值映射到输出组件的属性。这给了最大的灵活性，但代价是每个交互都要手写回调函数，代码量大且容易遗漏边界情况。marimo 的 reactive binding 是隐式的——cell 代码直接引用组件变量，依赖关系自动推导，无需注册回调。Dash 的优势在于它天然支持多页面应用和复杂的布局嵌套，marimo 教学版只支持单页面纵向布局。

## 教学版未实现的挑战

为保持代码可读，教学版省略了真实 marimo 的多个重要特性。**缓存**：真实版有基于内容寻址的缓存系统，避免重复计算相同输入的 cell；教学版每次都全量重跑。**多文件 notebook**：真实版支持 import 其他 notebook 作为模块；教学版只支持单文件。**SQL cell**：真实版有专门的 SQL cell 类型，连接数据库执行查询；教学版只有 Python cell。**富文本输出**：真实版支持 matplotlib 图表、pandas DataFrame 表格、自定义 MIME 类型输出；教学版只支持文本和 UI 组件。**文件持久化**：真实版 notebook 可保存为 `.py` 文件并恢复；教学版 session 结束即丢失。**多用户并发**：真实版支持多 session 隔离；教学版单 session 单连接。这些省略每一项都对应真实源码中数千行代码，但它们的核心思路都建立在本教学版已实现的骨架之上——理解了这 46 章的内容，就具备了阅读真实 marimo 源码的地图。
