# GitHub Pages 文档站

这套教学项目的文档本身也是一个可部署的网站，由 VitePress 构建，托管在 GitHub Pages 上。这一章我们看文档站的配置结构，以及 46 章内容是如何组织的。

## VitePress 配置

VitePress 是 Vue 官方的静态站点生成器，专为技术文档优化。项目根目录的 `docs/` 目录就是 VitePress 的源目录，配置文件在 `docs/.vitepress/config.ts`。核心配置包括：

```ts
export default defineConfig({
  title: "marimo 从零实现",
  description: "教学版 notebook 的完整构建指南",
  themeConfig: {
    sidebar: sidebarStructure,
    nav: navStructure,
  },
  base: "/marimo-from-scratch/",
})
```

`base` 设置为仓库名，这是 GitHub Pages 项目站点的标准要求——站点部署在 `https://user.github.io/marimo-from-scratch/`，所有资源 URL 都需要带这个前缀，VitePress 的 `base` 配置自动处理。

## 侧边栏结构

侧边栏按"篇"组织，共九篇 46 章。配置是一个嵌套数组：

```ts
const sidebarStructure = [
  {
    text: "第一篇 项目概览",
    items: [
      { text: "第1章 marimo 是什么", link: "/overview/ch01" },
      { text: "第2章 教学版范围", link: "/overview/ch02" },
    ],
  },
  // ... 第二篇到第九篇
  {
    text: "第九篇 部署与延伸",
    items: [
      { text: "第42章 从 notebook 到 web app", link: "/deployment/ch42" },
      // ...
    ],
  },
]
```

每篇对应一个子目录，每章对应一个 `.md` 文件。这种"目录即篇、文件即章"的结构让作者维护时只需在对应目录增删 `.md` 文件并更新侧边栏数组，VitePress 自动处理路由和构建。

## 46 章的组织逻辑

46 章按照从宏观到微观、从设计到实现的顺序排列。第一篇概览介绍项目目标和范围；第二篇搭建前后端骨架；第三到五篇实现核心的 cell 模型和执行器；第六到七篇实现前端编辑器和 cell 视图；第八篇（第 38-41 章）实现 UI 组件系统；第九篇（第 42-46 章）覆盖部署与延伸。读者可以按顺序通读，也可以根据兴趣跳转到特定篇。每章控制在 500-800 字，保证单次阅读 3-5 分钟即可完成，适合碎片化学习。

## 构建命令

文档站的构建命令是：

```bash
npm install
npm run build
```

`npm run build` 实际执行 `vitepress build docs`，把 `docs/` 下所有 markdown 编译成静态 HTML，输出到 `docs/.vitepress/dist/`。这个目录的内容就是要部署到 GitHub Pages 的产物。本地预览用 `npm run docs:dev`，启动 VitePress dev server，支持热重载，写作时修改 markdown 即时看到效果。构建产出的 HTML 已经预渲染了 Vue 组件，因此首屏加载无需客户端 JS 即可阅读，这对文档站的 SEO 和可访问性都很重要。
