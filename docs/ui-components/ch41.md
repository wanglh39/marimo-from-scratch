# 组件组合与布局

除了 Slider，marimo 教学版还实现了 Button 和 Checkbox 两种组件。它们的设计模式与 Slider 完全一致，但在交互语义上有重要区别。这一章我们看这三种组件如何协作，以及组件如何作为 cell 的输出。

## Button 实现

Button 的语义是"点击触发一次动作"，它没有持续的数值状态，只有一个瞬时的点击事件。在 `backend/components/ui.py` 中：

```python
class Button(UIComponent):
    def __init__(self, label="Click", value=0):
        self.component_type = "button"
        self.label = label
        self._value = value
        self.props = {"label": label}
```

`_value` 是一个点击计数器，每次前端回传时自增。前端渲染为一个 `<button>` 元素，`onClick` 触发时发送 `ui_event`，后端把 `_value` 加一。用户代码可以检查 `btn.value` 是否变化来决定是否执行某段逻辑。这种"计数器"模式比布尔标志更健壮——连续点击不会被合并成一次。

## Checkbox 实现

Checkbox 对应 `<input type="checkbox">`，表示一个布尔选择：

```python
class Checkbox(UIComponent):
    def __init__(self, label="Check", value=False):
        self.component_type = "checkbox"
        self.label = label
        self._value = value
        self.props = {"label": label}
```

前端渲染时，`checked` 属性绑定到 `component.value`，`onChange` 回调读取 `e.target.checked` 得到布尔值回传。Checkbox 常用于控制显示/隐藏逻辑，比如 `if show_advanced.value:` 决定是否执行某个 cell 的内容。

## 多组件协作

一个 cell 可以创建多个组件，它们作为独立的变量共存于同一命名空间：

```python
min_val = ui.slider(0, 50, 1, 0)
max_val = ui.slider(50, 100, 1, 100)
use_range = ui.checkbox("使用范围", True)
```

每个组件有独立的 `component_id`，前端为每个组件渲染独立的控件。当用户拖动 `min_val`，只有引用了 `min_val` 的后代 cell 重跑；拖动 `max_val` 只触发 `max_val` 的后代。这种细粒度的依赖追踪避免了"一个控件变化导致全 notebook 重跑"的低效。多个组件也可以共同被一个 cell 引用，比如 `filtered = data[(data["x"] >= min_val.value) & (data["x"] <= max_val.value)]`，此时 `min_val` 或 `max_val` 任一变化都会触发这个 cell 重跑。

## 组件作为 cell 输出

组件不仅可以在 cell 中作为变量使用，也可以直接作为 cell 的输出。当 cell 最后一行表达式是一个 UIComponent 时，executor 会把它加入该 cell 的输出列表，前端在 CellView 中渲染出对应控件。这种模式下，组件既是输入控件又是输出展示——比如一个 slider 既是用户调节参数的工具，又作为 cell 的可见输出展示当前值。这与传统 notebook 里"控件"和"输出"分离的模式不同，marimo 让两者统一为同一个 Python 对象，简化了心智模型。组合使用时，多个组件按创建顺序在前端纵向排列，教学版没有实现复杂的网格布局，这保持了实现的简洁，也符合教学项目的定位。
