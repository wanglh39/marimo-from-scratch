# Cell 组件：CellView 结构、状态图标、defs/refs 标签

`CellView.tsx` 是单个 cell 的完整 UI，把编辑器、输出、状态、元信息、操作按钮组合在一起。它是 notebook 前端最复杂的组件，但仍可拆成清晰的子区域。

## 整体结构

```tsx
function CellView({cell, onRun, onDelete, onUpdate}) {
  return (
    <div className="cell">
      <div className="cell-toolbar">
        <StatusIcon status={cell.status} />
        <span className="cell-id">{cell.id}</span>
        <DefsTags defs={cell.defs} />
        <RefsTags refs={cell.refs} />
        <button onClick={() => onRun(cell.id)}>Run</button>
        <button onClick={() => onDelete(cell.id)}>Del</button>
      </div>
      <CodeEditor
        value={cell.code}
        onChange={(code) => onUpdate(cell.id, code)}
        onRun={() => onRun(cell.id)}
      />
      <CellOutput result={cell.result} />
    </div>
  );
}
```

三段：工具栏、编辑器、输出。工具栏一行紧凑显示元信息和操作，编辑器占主体，输出在下方。

## 状态图标

`StatusIcon` 根据 `cell.status` 显示不同符号：

```tsx
function StatusIcon({status}) {
  const map = {
    idle:   "⬜",
    running: "⏳",
    done:    "✅",
    error:   "❌",
    stale:   "⚠️",
  };
  return <span className={`status status-${status}`}>{map[status]}</span>;
}
```

教学版用 emoji 简单直观。生产版用 SVG 图标加 CSS 动画（running 转圈）。状态值来自后端 `cell_result.status` 或 `state` 消息，前端不自己算——单一数据源在后端。

## defs/refs 标签

显示 cell 的依赖关系，帮用户理解图结构：

```tsx
function DefsTags({defs}) {
  return <span className="tags defs">
    {defs.map(d => <span className="tag def" key={d}>{d}</span>)}
  </span>;
}
```

defs 用绿色标签（"我产出这些"），refs 用蓝色（"我需要这些"）。点击标签可以做"跳转到定义 cell"等导航功能，教学版只显示不交互。

这些标签数据来自后端解析函数签名得到，前端只渲染。改代码后 `update_cell` 通知后端，后端重新解析 refs/defs，下条 `state` 或 `cell_result` 消息里带新值，前端自动更新——用户改 `return (y,)` 成 `return (y, z)`，几毫秒后 z 标签就冒出来。

## Run / Delete 按钮

Run 按钮触发 `onRun(cell.id)`，父组件发 `run_cell` 消息。Delete 触发 `remove_cell`。教学版按钮放工具栏；很多 notebook 还支持 cell 右侧悬浮按钮，CSS 即可调。

按钮状态联动：`cell.status === "running"` 时 Run 按钮置灰显示"运行中"，避免重复点击：

```tsx
<button disabled={cell.status === "running"} onClick={() => onRun(cell.id)}>
  {cell.status === "running" ? "..." : "Run"}
</button>
```

## 编辑器与输出的衔接

`CodeEditor` 的 `onChange` 把代码变化向上抛，父组件发 `update_cell`；`onRun` 抛 Shift-Enter 触发运行。`CellOutput` 根据 `cell.result` 渲染 stdout/output/exception，下一章详述。

CellView 本身不持有状态，全靠 props 驱动——这是 React 推荐的"提升状态到父组件"模式。父组件 `App` 持有 cells 数组，CellView 是纯展示+事件转发。这样 cell 间联动（运行 cell A 触发 cell B 重算后 B 的 UI 更新）通过父组件单一 state 自然完成，不需要 cell 间直接通信。
