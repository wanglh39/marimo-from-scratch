# 交互设计：Shift-Enter、暗色主题、连接指示器

前几章讲了结构和数据流，这一章聚焦**人机交互细节**。好的 notebook 要让用户手指不离键盘就能跑完一轮实验。marimo 前端的交互设计围绕效率、清晰、容错三个目标。

## Shift-Enter 运行

notebook 的肌肉记忆。在 CodeMirror 里绑定：

```typescript
keymap.of([{
  key: "Shift-Enter",
  run: () => { onRun(); return true; },
}])
```

`return true` 告诉 CM6 这个键已被处理，不要再冒泡（比如别换行）。`onRun` 由 CellView 传入，最终调 `useNotebook.runCell(cell.id)`。

进阶行为是"运行并跳到下一个 cell"——Run 完焦点自动移到下方 cell，连续按 Shift-Enter 能逐个跑下去。教学版可选实现：

```typescript
run: () => {
  onRun();
  onNextCell();
  return true;
}
```

`onNextCell` 由 App 层提供，调 `document.getElementById(nextCellId)?.focus()`。需要给每个 cell 的编辑器容器设可聚焦的 tabindex。

## 暗色主题

`index.css` 定义暗色主题。notebook 用户长时间盯屏幕，暗色减轻眼疲劳。配色：

```css
:root {
  --bg: #1e1e1e;
  --bg-cell: #252526;
  --bg-output: #1a1a1a;
  --text: #d4d4d4;
  --text-dim: #888;
  --accent: #4ec9b0;
  --error: #ff6b6b;
  --border: #3c3c3c;
}

body { background: var(--bg); color: var(--text); }
.cell {
  background: var(--bg-cell);
  border: 1px solid var(--border);
  border-radius: 4px;
  margin: 8px 0;
  padding: 12px;
}
.stdout, .output-json { background: var(--bg-output); color: var(--text); }
.exception { color: var(--error); background: #2a1515; }
.tag.def { color: var(--accent); }
```

CodeMirror 也要配暗色主题，用 `@codemirror/theme-one-dark`：

```typescript
import { oneDark } from "@codemirror/theme-one-dark";
// extensions 数组里加 oneDark
```

保持编辑器、输出、工具栏三区背景微妙差异（cell > body > output），形成层次感但不刺眼。

## 连接状态指示器

`App.tsx` 顶部一个指示器，让用户随时知道是否连着后端：

```tsx
function App() {
  const nb = useNotebook();
  return (
    <div className="app">
      <header className="app-header">
        <span className={`conn ${nb.connected ? "on" : "off"}`}>
          {nb.connected ? "● 已连接" : "○ 已断开"}
        </span>
        <button onClick={nb.runAll}>Run All</button>
        <button onClick={nb.addCell}>+ Cell</button>
      </header>
      <div className="cells">
        {nb.cells.map(c => <CellView key={c.id} cell={c} ... />)}
      </div>
    </div>
  );
}
```

```css
.conn.on { color: var(--accent); }
.conn.off { color: var(--error); animation: pulse 1s infinite; }
@keyframes pulse { 50% { opacity: 0.4; } }
```

断开时红色闪烁，连上时绿色稳定。这个指示器虽小，却是用户信任系统的基础——不然点 Run 没反应时不知道是自己操作错还是连接断了。

## Run All 与 Add Cell

`Run All` 发 `run_all` 消息，后端按拓扑序执行所有 cell，逐个推 `cell_result`，前端逐个更新——用户看到 cell 们从上到下依次变 running 再变 done，进度可视化。

`Add Cell` 发 `add_cell`，后端创建空 cell 并回 `graph_changed` 或 `state`，前端多渲染一个空 CellView，焦点自动落入新 cell 的编辑器，立即可输入。

## 容错：异常不阻塞

一个 cell 报错不应让整个 notebook 卡死。后端执行 cell 抛异常时回 `cell_result` 带 `exception`，前端那个 cell 显示红色 traceback，其他 cell 照常运行。Run All 遇到错误 cell 跳过下游继续（或停下，教学版可选策略），但 UI 始终响应——用户能改代码重跑。

交互设计的总原则：**让用户始终知道发生了什么、自己能做什么**。状态指示器说"系统能用"，状态图标说"cell 在干嘛"，Shift-Enter 让"跑一轮"变成一次按键，暗色主题让"长时间用"不痛苦。这些细节单独看都小，合起来决定 notebook 好不好用。
