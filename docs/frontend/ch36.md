# 前后端状态同步：useNotebook hook 与 WebSocket onmessage

`useNotebook.ts` 是前端的状态中枢。它维护 cells、edges、connected 三块状态，通过 WebSocket 与后端保持同步。所有组件都从它读状态、通过它发消息。这一章拆解它的实现。

## hook 的对外接口

```typescript
function useNotebook(): {
  cells: Cell[];
  edges: [string, string][];
  connected: boolean;
  runCell: (id: string) => void;
  runAll: () => void;
  updateCell: (id: string, code: string) => void;
  addCell: () => void;
  removeCell: (id: string) => void;
  sendUiEvent: (componentId: string, value: any) => void;
}
```

返回状态和一组动作函数。组件用 `const nb = useNotebook()` 拿到一切。动作函数内部往 WebSocket 发对应消息，不直接改 state——state 永远由后端消息驱动回写。

## 内部状态与 WebSocket

```typescript
function useNotebook() {
  const [cells, setCells] = useState<Cell[]>([]);
  const [edges, setEdges] = useState<[string,string][]>([]);
  const [connected, setConnected] = useState(false);
  const wsRef = useRef<WebSocket>();

  useEffect(() => {
    const ws = new WebSocket("ws://localhost:8000/ws");
    wsRef.current = ws;
    ws.onopen = () => {
      setConnected(true);
      ws.send(JSON.stringify({type: "get_state"}));
    };
    ws.onclose = () => setConnected(false);
    ws.onmessage = (e) => dispatch(JSON.parse(e.data));
    return () => ws.close();
  }, []);
  // ...动作函数...
  return {cells, edges, connected, runCell, ...};
}
```

mount 时建连接，`onopen` 立即请求全量状态。`onmessage` 把每条消息交给 `dispatch` 处理。

## dispatch：消息到状态的翻译

```typescript
function dispatch(msg) {
  switch (msg.type) {
    case "state":
      setCells(msg.cells.map(c => ({...c, result: c.result ?? null})));
      setEdges(msg.edges);
      break;
    case "cell_result":
      setCells(prev => prev.map(c =>
        c.id === msg.cell_id
          ? {...c, status: msg.status, result: msg.result}
          : c
      ));
      break;
    case "graph_changed":
      setEdges(msg.edges);
      setCells(prev => prev.map(c => {
        const fresh = msg.cells.find(m => m.id === c.id);
        return fresh ? {...c, refs: fresh.refs, defs: fresh.defs} : c;
      }));
      break;
    case "error":
      console.error(msg.message);
      break;
  }
}
```

- `state`：全量替换，用于初始化或重连；
- `cell_result`：只更新对应 cell 的 status 和 result，其余不动（避免不必要的重渲染）；
- `graph_changed`：依赖关系变了（用户改了函数签名），更新 edges 和 cell 的 refs/defs，但不碰 result——输出没变，只是图结构变了。

## 动作函数

```typescript
const runCell = (id) => wsRef.current?.send(JSON.stringify({type: "run_cell", cell_id: id}));
const updateCell = (id, code) => {
  setCells(prev => prev.map(c => c.id === id ? {...c, code} : c));
  wsRef.current?.send(JSON.stringify({type: "update_cell", cell_id: id, code}));
};
```

`updateCell` 有个细节：**乐观更新**——先改本地 state 让编辑器立即响应，再发消息给后端。若不发消息等后端确认，每次按键都要等往返，输入会卡。乐观更新的风险是后端拒绝时本地已改，教学版不处理这种冲突（后端基本不会拒绝 update_cell）。

`runCell` 不做乐观更新——运行结果是后端算的，前端不能预测，必须等 `cell_result` 回来。但可以立即把 status 置 running 让 UI 即时反馈：

```typescript
const runCell = (id) => {
  setCells(prev => prev.map(c => c.id === id ? {...c, status: "running"} : c));
  wsRef.current?.send(JSON.stringify({type: "run_cell", cell_id: id}));
};
```

## 单向数据流

整套机制遵循**单向数据流**：用户操作 → 动作函数发消息 → 后端处理 → 后端推消息 → dispatch 改 state → React 重渲染。state 永远由后端消息驱动，前端不自己算 cell 结果、不自己判依赖。这保证了前后端状态最终一致——前端是后端状态的投影，不会出现"前端显示 done 但后端其实 error"的分歧。

理解了 useNotebook，前端其他组件都只是"读 state + 调动作函数"的薄壳，复杂度全收拢在这个 hook 里。
