# CodeMirror 6 集成：EditorView、updateListener、外部同步

notebook 的代码编辑器是核心组件。marimo 前端用 CodeMirror 6（CM6），不是 Monaco 或 Ace。CM6 模块化、轻量、可 tree-shake，适合教学项目。但它的 API 是命令式且自管理 DOM，与 React 的声明式模型有张力，需要小心封装。这一章先讲 CM6 的架构三件套，再讲 React 封装的难点与解法，最后给出真实代码逐行注解。

## CM6 的架构三件套：EditorState、EditorView、Extension

CM6 的设计哲学是"组合优于继承"，核心由三个概念支撑：

- **EditorState**：不可变的编辑器状态快照。包含文档内容、选区、行装饰、标记集合等所有数据，以及一份扩展配置。每次 `dispatch` 产生新 state，旧 state 不变——这和 React 的不可变 state 同源，是 CM6 能与 React 协作的基础。
- **EditorView**：可变的视图，持有 DOM 节点和当前 state，提供 `dispatch` 改变状态。它是命令式 API，自己管 DOM 生命周期，React 不应直接操作它的 DOM。
- **Extension**：功能的统一抽象。语法高亮、快捷键、行号、主题、监听器都是 extension，拼在数组里传入 `EditorState.create`。extension 之间通过 **Facet** 协作——Facet 是"多输入聚合"机制，比如多个扩展都能贡献快捷键，keymap Facet 把它们合并成一个查找表。

创建编辑器的标准姿势：

```typescript
const view = new EditorView({
  state: EditorState.create({
    doc: initialCode,
    extensions: [python(), keymap.of([...]), updateListener],
  }),
  parent: divRef.current,
})
```

`python()` 提供 Python 语法高亮（来自 `@codemirror/lang-python`），`keymap` 绑定快捷键，`updateListener` 监听文档变化。每个都是 extension，组合在数组里。要加行号就 `lineNumbers()`，要换行就 `EditorView.lineWrapping`，要主题就传主题 extension——全是数组拼接，无需继承或配置对象嵌套。这种"插件数组"模型让 CM6 能 tree-shake 掉没用到的功能，打包体积可控。

## React 封装的难点

React 组件每次 render 会重新执行函数体，但 CM6 的 view 不能每次都重建——重建会丢光状态、闪烁、卡顿。所以要用 `useRef` 持有 view 实例，`useEffect` 里创建一次、卸载时销毁。下面是 `CodeEditor.tsx` 的真实实现，逐段注解：

```tsx
export function CodeEditor({ value, onChange, onRun }: Props) {
  const hostRef = useRef<HTMLDivElement>(null)
  const viewRef = useRef<EditorView | null>(null)
  const onChangeRef = useRef(onChange)
  const onRunRef = useRef(onRun)

  onChangeRef.current = onChange
  onRunRef.current = onRun
```

这里有个关键技巧：`onChange` 和 `onRun` 是 props，每次父组件 render 都可能是新函数引用。若直接在 CM6 的 keymap 里闭包捕获它们，捕获的是首次 render 的旧版本，后续父组件传新回调时编辑器还在调旧的——典型 stale closure bug。解法是用 ref 桥接：每次 render 把最新 props 写进 ref，CM6 回调里读 `onRunRef.current`，永远拿到最新值。这样 CM6 的 extension 配置只需建一次，不必随 props 变化重建。

```tsx
  useEffect(() => {
    if (!hostRef.current) return

    const view = new EditorView({
      state: EditorState.create({
        doc: value,
        extensions: [
          lineNumbers(),
          python(),
          keymap.of([...historyKeymap, ...defaultKeymap]),
          keymap.of([
            {
              key: 'Shift-Enter',
              run: () => {
                onRunRef.current?.()
                return true
              },
            },
          ]),
          EditorView.lineWrapping,
          EditorView.updateListener.of((update) => {
            if (update.docChanged) {
              onChangeRef.current(update.state.doc.toString())
            }
          }),
          EditorView.theme({
            '&': { fontSize: '14px', backgroundColor: 'transparent' },
            '.cm-content': { fontFamily: "'Consolas', 'Monaco', monospace" },
            '.cm-gutters': {
              backgroundColor: 'transparent',
              border: 'none',
              color: '#666',
            },
            '&.cm-focused': { outline: 'none' },
          }),
        ],
      }),
      parent: hostRef.current,
    })
    viewRef.current = view

    return () => view.destroy()
  }, [])
```

`useEffect` 依赖空数组，只在 mount 跑一次。extensions 数组里依次是：行号、Python 语法、默认快捷键（含历史 undo/redo）、Shift-Enter 运行键、自动换行、文档变化监听器、内联主题。`EditorView.theme` 用对象字面量定义 CSS，`&` 指编辑器根，`.cm-content` 指内容区，`&.cm-focused` 去掉聚焦轮廓让外观融入 cell。cleanup 调 `view.destroy()` 释放 DOM 和事件监听，防止卸载后泄漏。

## 外部 value 同步

上面封装有个 bug：`value` prop 变了（比如后端 `update_cell` 推回新代码，或父组件做格式化），编辑器不会更新——因为建 view 时只读了一次初始 `value`，之后 CM6 内部 state 自治。需要外部 value → 内部 state 的同步 effect：

```tsx
  useEffect(() => {
    const view = viewRef.current
    if (view && view.state.doc.toString() !== value) {
      view.dispatch({
        changes: { from: 0, to: view.state.doc.length, insert: value },
      })
    }
  }, [value])
```

判断 `view.state.doc.toString() !== value` 避免循环：用户输入触发 `onChange` → 父组件 setState → value prop 变 → 同步 effect 跑 → 但此时 CM6 内容已和 value 一致，跳过 dispatch。没有这个判断会形成"用户输入 → onChange → value 变 → dispatch 同样的内容 → 又触发 updateListener → onChange"的死循环，虽不无限但每次按键多一次无谓 dispatch，浪费且可能扰动光标。

`changes: {from: 0, to: length, insert: value}` 是"全量替换"写法，简单粗暴但够用。生产版可计算 diff 只替换变化区间，减少 undo 历史污染——教学版不必。

## updateListener 的用途

`EditorView.updateListener.of(cb)` 在每次 dispatch 后调用，`cb` 收到 `Update` 对象能查 `update.docChanged`、`update.selectionSet`、`update.focusChanged` 等。用它做：

- 文档变化时 `onChange` 通知父组件（教学版用了）；
- 选区变化时更新光标位置（若需要在状态栏显示行列号）；
- 焦点变化时通知父组件（用于 Shift-Enter 只在当前 cell 触发 run，避免多个 cell 同时响应）。

`updateListener` 与 `EditorView.domEventHandlers` 的区别：前者监听的是 state 变化（语义层），后者监听原生 DOM 事件（如 keydown 之前）。一般用 updateListener 够了，要拦截原始键盘事件才用 domEventHandlers。

## Facet 与扩展协作

理解 Facet 有助调试"为什么我的快捷键没生效"。CM6 里 keymap 是 Facet，多个 `keymap.of([...])` 都向它贡献绑定，按"后注册优先"匹配。所以教学版把 Shift-Enter 单独 `keymap.of` 放在 `defaultKeymap` 之后，确保 Shift-Enter 优先于默认的换行行为。若顺序反了，Shift-Enter 会被 defaultKeymap 当普通 Enter 处理换行，run 不触发。

同理 `lineNumbers()` 贡献 gutter Facet，多个扩展都能加 gutter（行号、断点、fold 标记），CM6 按顺序排列。这种"多输入聚合"让扩展能正交组合，是 CM6 模块化的底层机制。

## 为什么不用 react-codemirror2

社区有 `@uiw/react-codemirror` 等封装库，省去手写 effect。教学版手写是为了让读者看清 CM6 与 React 的边界——封装库藏起同步逻辑，遇到 bug 反而难调。比如"输入光标跳到末尾"这个常见 bug，根因就是外部 value 同步 effect 没判断内容是否一致，无脑 dispatch 全量替换。理解了这套手写封装，再用封装库就心里有数：知道它在 effect 里做了什么、stale closure 怎么避免、循环怎么切断。

CM6 集成的核心就三件事：**mount 时建 view、unmount 时销毁、外部 value 变化时 dispatch 同步**。其余扩展（高亮、keymap、listener、主题）都是配置项，加在 `extensions` 数组里即可。下一章讲 CellView 如何把编辑器、输出、状态标签组合成完整 cell。
