# 输出渲染：stdout、output、exception 与 UI 组件

cell 执行结果有三种形态：标准输出、返回值、异常。`CellOutput` 组件要分别渲染。还要识别 marimo UI 组件（滑块、按钮等）做特殊渲染。这一章拆解 `CellOutput` 的实现。

## result 的数据结构

后端 `cell_result` 消息里 `result` 字段长这样：

```json
{
  "stdout": "hello world\n",
  "output": {"type": "json", "data": 42},
  "exception": null,
  "ui_components": [{"id": "s0", "type": "slider", "value": 5, "min": 0, "max": 10}]
}
```

- `stdout`：print 出来的文本，纯字符串；
- `output`：最后一个表达式的值，经 `serialize_output` 序列化；
- `exception`：traceback 字符串，正常时为 null；
- `ui_components`：cell 里创建的 marimo UI 组件描述。

## 分区渲染

```tsx
function CellOutput({result}) {
  if (!result) return null;
  return (
    <div className="cell-output">
      {result.exception ? (
        <ExceptionView traceback={result.exception} />
      ) : (
        <>
          <StdoutView text={result.stdout} />
          <OutputView output={result.output} />
          <UIComponentsView components={result.ui_components} />
        </>
      )}
    </div>
  );
}
```

有异常时只显示异常（执行失败，stdout 可能也有但不重要，教学版简化为只显 traceback）。正常时三段依次显示。

## StdoutView

最简单，`<pre>` 包一下保留换行：

```tsx
function StdoutView({text}) {
  if (!text) return null;
  return <pre className="stdout">{text}</pre>;
}
```

## OutputView

根据 `output.type` 分支：

```tsx
function OutputView({output}) {
  if (!output) return null;
  if (output.type === "json") {
    const data = output.data;
    if (typeof data === "string") return <pre className="output-str">{data}</pre>;
    if (typeof data === "number" || typeof data === "boolean")
      return <span className="output-num">{String(data)}</span>;
    return <pre className="output-json">{JSON.stringify(data, null, 2)}</pre>;
  }
  return <pre className="output-repr">{output.data}</pre>;
}
```

JSON 类型里再按具体类型细分：字符串直接显示（多行保留），数字布尔简短显示，对象数组用 `JSON.stringify` 缩进显示。`type === "repr"` 是 `serialize_output` 退回 repr 的情况，当文本显示。

## ExceptionView

traceback 是多行字符串，红色等宽字体显示：

```tsx
function ExceptionView({traceback}) {
  return <pre className="exception">{traceback}</pre>;
}
```

CSS 里 `.exception { color: #ff6b6b; background: #2a1515; }` 配暗色主题显眼但不刺眼。

## UIComponentsView

这是 marimo 区别于普通 notebook 的关键：cell 能产出**交互组件**。后端把 cell 里 `mo.slider(0, 10)` 这类调用序列化成描述发过来，前端渲染成真组件：

```tsx
function UIComponentsView({components}) {
  return <>{components.map(c => <UIComponent key={c.id} comp={c} />)}</>;
}

function UIComponent({comp}) {
  switch (comp.type) {
    case "slider":
      return <input type="range" min={comp.min} max={comp.max}
        value={comp.value}
        onChange={e => sendUiEvent(comp.id, Number(e.target.value))} />;
    case "button":
      return <button onClick={() => sendUiEvent(comp.id, null)}>{comp.label}</button>;
    default:
      return <span>未知组件: {comp.type}</span>;
  }
}
```

`sendUiEvent` 发 `ui_event` 消息给后端，后端调用对应 Python 回调，可能触发重算，新结果推回来——这就是 marimo reactive UI 的闭环。

## 组件 ID 与 _update_component_ids

后端 `NotebookSession._update_component_ids` 给每个 UI 组件分配稳定 ID（基于 cell ID + 出现位置），保证前端重渲染时组件 ID 不变、React key 稳定、不丢组件内部状态（比如滑块正在拖动）。

输出渲染的核心是**按数据类型分支 + UI 组件特殊处理**。教学版覆盖 stdout/基本类型/异常/滑块/按钮五种，生产版加图表、表格、Markdown 等，但模式一致：后端序列化成描述，前端按描述渲染。
