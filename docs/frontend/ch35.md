# 输出渲染：stdout、output、exception 与 UI 组件

cell 执行结果有三种形态：标准输出、返回值、异常。`CellOutput` 组件要分别渲染。还要识别 marimo UI 组件（滑块、按钮等）做特殊渲染。这一章拆解 `CellView` 里输出区的实现，重点是**类型判断逻辑**——后端序列化的数据结构决定前端如何分支渲染。

## result 的数据结构

后端 `cell_result` 消息里与输出相关的字段拆开看：

```typescript
export interface CellResultMessage {
  type: 'cell_result'
  cell_id: string
  status: CellStatus
  output: unknown          // 最后一个表达式的值，序列化后
  stdout: string            // print 累积的文本
  exception: string | null  // traceback 字符串
  exception_type: string | null  // 异常类型名，如 "NameError"
  components: UIComponentInfo[]  // cell 里创建的 UI 组件
}
```

对应到 `CellInfo`，前端 state 里每个 cell 都有这几个字段。举例一条真实结果：

```json
{
  "stdout": "hello world\n",
  "output": 42,
  "exception": null,
  "exception_type": null,
  "components": [
    {"_ui": true, "id": "s0", "type": "slider", "value": 5, "props": {"min": 0, "max": 10}}
  ]
}
```

- `stdout`：print 出来的文本，纯字符串，可能多行；
- `output`：最后一个表达式的值，经 `serialize_output` 序列化，可能是 number/string/boolean/object/array，也可能是 UI 组件描述（带 `_ui: true` 标记）；
- `exception` / `exception_type`：traceback 字符串和异常类名，正常时为 null；
- `components`：cell 里通过 `mo.slider()` 等创建的 UI 组件描述数组。

## 输出区的渲染条件

`CellView` 里输出区不是无条件渲染，而是判断"有内容才显示"：

```tsx
{(cell.stdout || cell.output !== null || cell.exception) && (
  <div className="cell-output">
    {cell.stdout && <pre className="output-stdout">{cell.stdout}</pre>}
    {cell.output !== null && !outputIsUI && (
      <pre className="output-value">
        {typeof cell.output === 'string'
          ? cell.output
          : JSON.stringify(cell.output, null, 2)}
      </pre>
    )}
    {outputIsUI && (
      <UIComponentView component={cell.output as UIComponentInfo} onEvent={onUIEvent} />
    )}
    {cell.exception && (
      <pre className="output-error">{cell.exception_type}: {cell.exception}</pre>
    )}
  </div>
)}
```

外层条件 `cell.stdout || cell.output !== null || cell.exception` 避免空 cell 渲染一个空输出框。内层每段各自判断：有 stdout 才显 stdout，有 output 且不是 UI 才显值，output 是 UI 才显组件，有 exception 才显错误。这种"每段独立条件"让输出区能灵活组合——一个 cell 可能同时有 stdout（print 了点东西）和 output（返回了值），两段都显示。

## outputIsUI 的类型判断

关键判断在组件顶部：

```tsx
const outputIsUI =
  cell.output !== null &&
  typeof cell.output === 'object' &&
  (cell.output as Record<string, unknown>)?._ui === true
```

三重判断：非 null、是对象、`_ui` 字段为 true。后端 `serialize_output` 把 `mo.slider()` 等返回的 UI 组件序列化成带 `_ui: true` 标记的对象，前端据此分支——UI 组件用 `UIComponentView` 渲染成可交互控件，普通对象用 `JSON.stringify` 当数据展示。这个 `_ui` 标记是前后端约定的小协议，让前端能从序列化结果里识别"这是组件描述不是普通数据"。

## StdoutView

最简单，`<pre>` 包一下保留换行：

```tsx
{cell.stdout && <pre className="output-stdout">{cell.stdout}</pre>}
```

CSS 里 `.output-stdout { color: var(--text); }` 用主文本色，`.cell-output pre { white-space: pre-wrap; word-break: break-word; }` 让长行自动换行不溢出。`pre` 标签保留空白和换行，适合显示 print 输出。

## OutputView 的类型分支

output 渲染分两条路：UI 组件走 `UIComponentView`，普通值走 JSON 展示：

```tsx
{cell.output !== null && !outputIsUI && (
  <pre className="output-value">
    {typeof cell.output === 'string'
      ? cell.output
      : JSON.stringify(cell.output, null, 2)}
  </pre>
)}
```

`typeof cell.output === 'string'` 时直接显示字符串（可能多行，`pre` 保留换行），否则 `JSON.stringify(output, null, 2)` 缩进 2 空格格式化。number/boolean/object/array 都走 JSON.stringify：数字 `42` 显示 "42"，布尔 `true` 显示 "true"，对象 `{"a": 1}` 显示多行 JSON，数组同理。

教学版没细分 number/boolean/object 的展示样式，统一 JSON.stringify。生产版会按类型分别渲染：数字用等宽对齐、对象用可折叠树、数组用表格、字符串多行保留。但模式一致：**后端序列化成结构化数据，前端按 type 分支渲染**。教学版简化为"字符串直显 + 其余 JSON"，覆盖大部分场景。

## ExceptionView

traceback 是多行字符串，配 `exception_type` 显示：

```tsx
{cell.exception && (
  <pre className="output-error">{cell.exception_type}: {cell.exception}</pre>
)}
```

CSS 里 `.output-error { color: var(--red); margin-top: 4px; }` 红色显眼。同时根 div 的 `cell-${cell.status}` 在 status 为 error 时加 `cell-error` 类，CSS `.cell-error { border-color: var(--red); }` 让整个 cell 边框变红，远看就能定位出错 cell。`exception_type` 单独显示（如 "NameError: name 'x' is not defined"）让用户不读完整 traceback 就知道错误类型。

有异常时输出区只显异常，不显 stdout/output——执行失败时 stdout 可能也有（print 在异常前执行了），但教学版简化为只显 traceback，避免成功输出和错误混在一起干扰排错。生产版可分 tab 或折叠显示 stdout。

## UIComponentsView

这是 marimo 区别于普通 notebook 的关键：cell 能产出**交互组件**。分两种位置：`cell.components` 是 cell 执行过程中创建的组件（如 `s = mo.slider(0,10)`），`cell.output` 是 cell 直接返回的组件（如 `return mo.slider(0,10)`）。两者都用 `UIComponentView` 渲染：

```tsx
function UIComponentView({ component, onEvent }: {
  component: UIComponentInfo
  onEvent: (id: string, value: unknown) => void
}) {
  if (!component.id) return null

  switch (component.type) {
    case 'slider':
      return (
        <div className="ui-component">
          <input
            type="range"
            min={component.props.min as number}
            max={component.props.max as number}
            step={component.props.step as number}
            value={component.value as number}
            onChange={(e) => onEvent(component.id!, Number(e.target.value))}
          />
          <span className="ui-value">{String(component.value)}</span>
        </div>
      )
    case 'button':
      return (
        <div className="ui-component">
          <button className="ui-button" onClick={() =>
            onEvent(component.id!, (component.value as number) + 1)
          }>
            {component.props.label as string}
          </button>
          <span className="ui-value">clicks: {String(component.value)}</span>
        </div>
      )
    case 'checkbox':
      return (
        <div className="ui-component">
          <label className="ui-checkbox">
            <input
              type="checkbox"
              checked={component.value as boolean}
              onChange={(e) => onEvent(component.id!, e.target.checked)}
            />
            {component.props.label as string}
          </label>
        </div>
      )
    default:
      return null
  }
}
```

`component.id` 为 null 时返回 null——组件还没被后端分配 id，不渲染避免事件发不出去。`switch (component.type)` 按类型分支：slider 渲染 `<input type="range">`，配 `min/max/step/value` 从 `component.props` 取；button 渲染 `<button>`，点击时 value 加 1（计数器语义）；checkbox 渲染 `<input type="checkbox">`。每种组件旁都有 `ui-value` 显示当前值，让用户看到组件状态。

事件通过 `onEvent(component.id, newValue)` 上抛，最终发 `ui_event` 消息给后端，后端调用对应 Python 回调，可能触发重算，新结果推回来——这就是 marimo reactive UI 的闭环：拖滑块 → 前端发 ui_event → 后端调回调 → 重算依赖 cell → 推 cell_result → 前端刷输出。

## 组件 ID 与 _update_component_ids

后端 `NotebookSession._update_component_ids` 给每个 UI 组件分配稳定 ID（基于 cell ID + 出现位置），保证前端重渲染时组件 ID 不变、React key 稳定、不丢组件内部状态（比如滑块正在拖动）。若 ID 不稳定，每次重渲染滑块都被卸载重建，拖动中断、焦点丢失。稳定 ID 是交互流畅的底层保障。

输出渲染的核心是**按数据类型分支 + UI 组件特殊处理**。教学版覆盖 stdout/基本类型/异常/滑块/按钮/checkbox 六种，生产版加图表、表格、Markdown、DataFrame 等，但模式一致：后端序列化成描述，前端按描述渲染。下一章讲这些状态如何通过 WebSocket 与后端保持同步。
