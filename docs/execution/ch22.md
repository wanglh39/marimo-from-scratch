# output 与 stdout 提取

cell 执行完，用户想看到的不只是"成功/失败"的状态，还有代码产出的值和打印的文本。传统 notebook 里这两者混在一起：最后一个表达式的值和 `print` 的输出都显示在 cell 下方。marimo 的执行引擎需要把两者都捕获并区分开，分别作为 `output` 和 `stdout` 返回。这一章讲清楚提取逻辑。

## output：最后一条 Expr 的值

Python 的 `exec` 默认不返回值，`x = 1` 执行后只是给命名空间赋值，没有"返回值"概念。但 notebook 里 `x + 1` 这种裸表达式，用户期望看到它的值。marimo 的做法是：编译 cell 代码后，检查 AST 的最后一条语句；若它是 `ast.Expr`（即裸表达式），就单独 `eval` 这一条取值：

```python
tree = ast.parse(cell.code)
if tree.body and isinstance(tree.body[-1], ast.Expr):
    last_expr = ast.Expression(body=tree.body[-1].value)
    output = eval(compile(last_expr, "<cell>", "eval"), self._global_ns)
else:
    output = None
```

前面的语句照常 `exec`（赋值、函数定义等副作用），只有最后一条如果是表达式才额外 `eval` 取值。这样 `x = 1` 的 output 是 `None`（赋值语句不是 Expr），`x + 1` 的 output 是 2，`print("hi"); 42` 的 output 是 42。这个语义和 Jupyter 一致：只有最后一个裸表达式的值被显示。注意要把最后一条从 `exec` 的代码里去掉或保持幂等——教学版简化处理，先 `exec` 整段，再 `eval` 最后一条，对纯表达式无副作用的情况是正确的；严格做法是 `exec` 除最后一条外的语句，再 `eval` 最后一条，避免重复执行。

## stdout：redirect_stdout 捕获 print

`print` 写到 `sys.stdout`，默认是终端。要捕获它，用 `contextlib.redirect_stdout` 把 `sys.stdout` 临时换成一个 `StringIO`：

```python
import io, contextlib
buf = io.StringIO()
with contextlib.redirect_stdout(buf):
    exec(code, self._global_ns)
stdout = buf.getvalue()
```

执行期间所有 `print` 都写进 `buf`，执行完 `getvalue()` 取出全部文本。`with` 块退出后 `sys.stdout` 自动恢复，不影响后续 cell 或前端通信。注意要在同一次执行里同时捕获 stdout 和算 output：先在 `redirect_stdout` 上下文里 `exec` 前面所有语句，再在同一个上下文里 `eval` 最后一条（若表达式有副作用或触发 print 也要捕获），最后出 with 取 stdout。

## 两者的区分与展示

`output` 是结构化的值，前端可以用富文本渲染（表格、图表、HTML）；`stdout` 是纯文本，按原样显示在 monospace 块里。区分开能让 DataFrame 显示成表格而非 `__repr__` 字符串，让 matplotlib 图显示成图片而非文本。执行引擎把 `(output, stdout, status, error)` 一起返回，前端按类型分发渲染器。这种"值和文本分离"的设计，是 marimo 输出体验比传统终端式 notebook 更好的底层原因。
