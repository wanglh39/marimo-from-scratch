# 短路机制

notebook 执行时，某个 cell 报错是常态：除以零、文件不存在、键不存在……如果不管错误继续往下跑，下游 cell 会拿到缺失或过期的变量，要么报一堆连锁错误，要么更糟——静默用过期值算出错误结果。marimo 用"短路"机制处理这个问题：出错的 cell 标记失败，它的所有后代不再执行，直接标记为 STALE（过期），等用户修复源头后自动恢复。

## cell 出错后 short_circuited=True

`run_cell` 执行每个 cell 时用 try/except 包裹。一旦抛异常，就把该 cell 的状态置为 `ERRORED`，并设置 `short_circuited = True`，立即跳出循环：

```python
for cid in order:
    if self._has_failed_upstream(cid):
        self._mark_stale(cid)
        continue
    try:
        self._exec_cell(cid)
    except Exception:
        self._cells[cid].status = ERRORED
        short_circuited = True
        break
```

`break` 之后，循环里还没处理的 cell 全部留给下面的 STALE 标记逻辑。这样一次执行最多只有一个 cell 报错（第一个碰到的），避免连锁异常刷屏。

## 后代标记 STALE

短路之后，出错 cell 的后代都标为 STALE。STALE 表示"这个 cell 的输入可能已经不一致，结果不可信，需要重跑才能恢复"。前端据此给这些 cell 加上视觉标记（比如灰色或黄色边框），告诉用户"这里的输出是旧的，别当真"。标记 STALE 不执行代码，所以不会产生新的错误，只是状态更新。

## _has_failed_upstream 检查

在执行某个 cell 之前，要先确认它的所有上游都健康。`_has_failed_upstream(cid)` 检查 `ancestors(cid)` 里有没有 `ERRORED` 或 `STALE` 的 cell：

```python
def _has_failed_upstream(self, cid):
    for anc in self._graph.ancestors(cid):
        if self._cells[anc].status in (ERRORED, STALE):
            return True
    return False
```

若有，当前 cell 不执行，直接标 STALE。这处理的是"增量执行时，出错 cell 不在本次 `order` 里，但它的后代在"的情况——比如用户改了下游某个 cell，触发 `run_cell`，执行集合里不含出错的源头 cell，但含它的后代，这时靠 `_has_failed_upstream` 把后代挡住。

## 修复后自动恢复

短路不是终态。用户修好出错的 cell（比如把除数改成非零），再次触发执行时：源头 cell 重新执行成功，状态变回 `OK`；它的后代在本次 `order` 里，`_has_failed_upstream` 返回 False，于是正常执行，STALE 状态被覆盖为 `OK`。整条链路自动恢复，无需用户手动"重跑全部"。这种"出错即短路，修复即恢复"的行为，让 notebook 在频繁试错时保持清爽：错误不会向下游蔓延，修复后下游自动跟上。
