# 拓扑排序：Kahn 算法

执行引擎要回答的第一个问题是"按什么顺序跑这些 cell"。答案就是 DAG 的拓扑序，而 `CellGraph.topological_order` 用的是 Kahn 算法——一种基于入度的经典方法，既能在 $O(V+E)$ 时间内排出序，又能顺带检测环。这一章我们拆开它的实现细节。

## 入度法

入度（in-degree）指指向某个顶点的边数。Kahn 算法的直觉是：入度为 0 的 cell 不依赖任何其他 cell，可以最先执行；执行完把它"摘掉"，它指向的后继就少了一条入边，入度随之减一；若某个后继的入度减到 0，它就成了新的"无依赖"cell，可以执行。如此反复，就像剥洋葱一样一层层去掉无依赖的顶点。

具体步骤：

1. 计算每个顶点的初始入度。
2. 把所有入度为 0 的顶点放进一个待处理队列。
3. 从队列取出一个顶点 $u$，追加到结果序列 `order`；对 $u$ 的每个后继 $v$，把 $v$ 的入度减一，若减到 0 就把 $v$ 入队。
4. 重复第 3 步直到队列为空。

若最终 `len(order) == V`，排序成功；否则图里有环，剩下的顶点入度永远降不到 0。

## sorted 保证确定性

一个 DAG 通常有多种拓扑序。比如三个互不依赖的 cell `a, b, c`，任何排列都是合法拓扑序。但 marimo 需要每次得到同一个序列，否则执行结果可能因顺序不同而漂移（比如多个 cell 都往同一个文件写，顺序就重要）。为此，Kahn 在把入度为 0 的顶点入队时，先按 cell id 排序：

```python
ready = sorted([v for v in cells if indeg[v] == 0])
while ready:
    u = ready.pop(0)
    order.append(u)
    for v in sorted(successors(u)):
        indeg[v] -= 1
        if indeg[v] == 0:
            ready.append(v)
    ready.sort()
```

每次往 `ready` 里加新元素后重新排序，保证同一时刻有多个可选顶点时，总选 id 最小的。这样得到的拓扑序是唯一的、可复现的，对调试和测试都极其重要。

## 时间复杂度 O(V+E)

建入度表要遍历所有边，$O(E)$；主循环里每个顶点出队一次，每条边在"减后继入度"时被访问一次，合计 $O(V+E)$。`sorted` 的加入会让单次排序付出 $O(k \log k)$，最坏情况下整体退化为 $O(V \log V + E)$，对 notebook 规模（几百到几千个 cell）完全可接受。`execution_order_from` 在这个基础上再做一次过滤，只保留某个 cell 及其后代，用于增量执行——它先取后代集合，再在全局拓扑序里筛出属于该集合的顶点，保持相对顺序，从而得到子图的拓扑序。这样增量执行和全量执行共用同一套排序逻辑，行为一致。
